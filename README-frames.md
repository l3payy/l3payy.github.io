# Frame — папки экранов

Одна папка внутри `Frame/` = один экран на сайте. Порядок — по номеру папки.

```
Frame/
  1/
    1_1.svg          # обязательный: большой цветной текст
    1_2.svg          # опциональный: белый бейдж по центру
    1_3.svg          # опционально: акцентная обводка под бейджем
    label.txt        # опционально: подпись для SEO/aria
  2/
    2_1.svg
    2_2.svg
  3/
    3_1.svg
```

Ссылки на экраны — в отдельном `link.js` в корне проекта.

## Правила

- `N_1.svg` — главный текст. Растягивается на всю ширину и высоту экрана, красится акцентным цветом.
- `N_2.svg` — опциональный белый бейдж. Показывается по центру. Ширина адаптивная: не больше натуральной ширины SVG и не больше `86vw`, пропорции сохраняются по размерам из файла. На телефоне бейдж занимает около 86% ширины экрана. Если есть `N_3.svg`, при сборке белым путям добавляется белая обводка 2 px: она закрывает щели между текстом и обводкой, размеры SVG не меняются.
- `N_3.svg` — опциональная обводка бейджа. Лежит под `N_2`, красится акцентным цветом через маску. Размеры обоих SVG не меняются: они центрируются друг на друге.
- `label.txt` — подпись экрана (например, `Focus`). Если нет — будет `Frame N`.
- Ссылки задаются отдельно в `link.js` по номеру папки:
  ```js
  window.FRAME_LINKS = {
    "1": "https://...",
    "2": ""
  };
  ```
  Если ключа нет или ссылка пустая — клик по этому экрану ничего не открывает. `link.js` не пересобирается: изменил файл → обновил страницу.
- Все SVG из `Frame/` копируются в `assets/frames/`: главный текст нормализуется для растяжения, бейдж копируется с заливочной обводкой (если есть `N_3`), обводка — как есть.
- Фоновое видео растягивается на весь экран (`object-fit: fill`), как и основной текст фрейма.
- Основной текст ограничен по ширине `62.5vw` (на экране 1920 px это 1200 px) и центрируется. В портретной ориентации ограничение отключается, текст занимает всю ширину.

## Обновить сайт

После добавления/удаления папок:

```bash
node build-frames.js
```

Или запустить `start.cmd` — он сам пересоберёт фреймы и поднимет локальный сервер на `http://127.0.0.1:4173/`.

Генерируются:

- `frames.js` — список фреймов для сайта;
- `frames.json` — тот же список для проверки;
- `assets/frames/` — нормализованные копии SVG.

`frames.js` и `assets/frames/` руками не редактируются.

## Локальный просмотр

`Preview Site.lnk` (или `start.cmd`) собирает фреймы и открывает `http://127.0.0.1:4173/`. Если сервер уже запущен, скрипт просто пересоберёт фреймы и откроет вкладку.

При сборке версии `bg.mp4` и `bg-poster.jpg` обновляются по хешу файла. Поэтому заменённый фон подхватывается без ручной очистки кеша — достаточно снова запустить превью.

## Пуш на GitHub

`Push Site.lnk`:

1. собирает фреймы в `NewPortfolio`;
2. копирует всё содержимое `NewPortfolio` в `C:\Program Files\Git\site`, кроме `.git` и `node_modules`;
3. делает `git add -A`, commit и push из `C:\Program Files\Git\site`.

История репозитория сохраняется, потому что `.git` не копируется. Старые файлы, которых нет в `NewPortfolio`, не удаляются — они просто остаются в папке.

Редактировать сайт нужно в `NewPortfolio`: при следующем `Push Site` папка старого сайта будет перезаписана её содержимым.
